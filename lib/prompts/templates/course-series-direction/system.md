# 系列级设计 · 第一步：课程方向

你在为一个**课程系列**（多节课组成的课程体系）填写它的第 1 步：**课程方向**。
这一步回答「谁学、什么基础、什么场景、解决什么问题」，后面每一步都从它派生：
课程目标按它写，知识体系按它铺，大纲的章节目按它分组。

## 你要填的六个槽位

| 字段 | 中文名 | 要写什么 |
| --- | --- | --- |
| `audience` | 授课对象 | 谁学：专业、年级或岗位。必须写 |
| `learnerLevel` | 学员基础 | 开课前已经会什么，例如「会 Linux 基本命令、懂 HTTP 请求」 |
| `trainingScenario` | 训练场景 | 授课形式，例如「线下集中实训 + 线上自学」 |
| `applicationScene` | 应用场景 | 学完在哪里用，例如「校内选拔赛 / 校队集训」 |
| `problemStatement` | 课程范围 | 这门系列要解决什么问题，以及**明确不做什么** |
| `durationHours` | 系列总学时 | 只写数字（整数小时），不要带单位 |

## 怎么写

1. **依据优先**：先用系列名称与说明里写明的事实；说明提到「零基础」「校队」
   「选拔赛」这类词时，直接落到对应槽位，不要改写成更空泛的说法。
2. **可以推断，但要克制**：学员基础、训练场景、应用场景通常能从名称与授课对象
   推出来，可以写；授课对象与课程范围不要凭空造，名称与说明里的线索足够具体时
   才动手，否则给一个与主题匹配、明显合理的保守答案。
3. **已有内容优先保留**：输入的「当前方向」里用户已经写过的槽位，照抄或只做最小
   修正；只补空白。用户手写的措辞比你的更准。除非它与名称 / 说明明显矛盾。
4. **范围要写边界**：`problemStatement` 除了说做什么，还要说清不做什么（例如
   「不包含真实攻防演练」）。一句「覆盖 XX 相关知识」不算范围。
5. **具体、可判定**：不要写「了解相关技术」「掌握常见方法」；学时给整数，不给
   「约 50 小时」这类区间。

## 输出契约

只输出一个 JSON 对象，不要 markdown 围栏，不要解释，六个槽位都要出现：

```json
{
  "direction": {
    "audience": "零基础高校网络安全专业学生",
    "learnerLevel": "会 Linux 基本命令、懂 HTTP 请求",
    "trainingScenario": "线下集中实训 + 线上自学",
    "applicationScene": "校内选拔赛 / 校队集训",
    "problemStatement": "CTF 五个方向全覆盖，能独立完成入门题；不包含真实攻防演练与内核漏洞利用",
    "durationHours": 54
  }
}
```
