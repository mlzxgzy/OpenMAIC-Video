# 系列级设计 · 第二步：课程目标候选清单

你在为一个**课程系列**生成第 2 步「课程目标与证据」的**候选清单**。课程负责人会
在清单里勾选要采用的目标，所以你的任务不是"给出最终答案"，而是**给出一批值得
挑的目标**：覆盖不同层次、彼此不重复、每一条都能被验证。

课程目标是**整个系列**的承诺（不是某一节课的内容）：学完这条系列，学员能做出
什么。它会被每个目承接，目再为它准备证据、安排教学。

## 类型：每条候选必须属于四类之一

| `type` | 中文 | 回答的问题 | 长什么样 |
| --- | --- | --- | --- |
| `knowledge` | 知识 | 学员**理解**了什么机制 / 原理 / 规则 | 「能解释 SQL 注入为什么会触发，并说出联合注入与报错注入的差别」 |
| `skill` | 技能 | 学员**会做**某个具体操作 | 「能独立用 sqlmap 跑完一次联合注入并取出目标数据」 |
| `competency` | 能力 | 学员能在**陌生问题**上综合运用，独立做完一件事 | 「能面对没见过的 Web 靶场，从信息收集走到拿到 flag」 |
| `task` | 任务 | 学员能交付一件**外部可检查的成果** | 「能独立完成一套入门赛题，并写出可复现的 Writeup」 |

四类由浅到深：知识 → 技能 → 能力 → 任务。不要把所有东西都写成「技能」：一条
系列如果只有技能，学员会做步骤但不会解决问题；只有任务，学员会做项目但说不清
原理。**这次生成的就是要让负责人有得挑，所以四类都要有。**

## 数量与分布

- 一共生成 **18–28 条**候选。宁多勿少：用户是来挑选的。
- 四类都要有，建议分布：知识 4–6 条、技能 6–8 条、能力 4–6 条、任务 3–5 条。
- 同一类内部按**由浅入深**排列；整体按 `knowledge → skill → competency → task` 排列。

## 每条候选必须包含四样

1. `title`：一句话说清这条目标是什么（不超过 40 字）。
2. `expectedBehavior`：**可观察的行为**——看到学员做什么，就能判断达标没有。
   不要写「了解」「熟悉」「掌握」「理解」作为行为；写「能解释…」「能独立完成…」
   「能定位…并修复…」。
3. `minCriteria`：最低达标线，**至少一条**，可判定。例如「独立完成，不参照
   Writeup」「10 道题至少答对 8 道」「提交的 flag 正确且过程可复现」。
4. `evidence`：课程里**怎么证明**这条目标达成——理论题、靶场实操、作品、考试
   记录，写成一句可执行的话。必须是这门系列真的能收集到的证据，不要编造不存
   在的考核方式。

## 依据与边界

1. **依据方向写**：学员基础、训练场景、应用场景、课程范围都在输入里。目标是
   这门系列承诺的东西，不要承诺范围之外的能力（范围里写「不包含内网渗透」就
   不要出「能完成内网横向移动」）。
2. **不要重复已有目标**：输入会列出已有的课程目标。不要换一种说法重复它们；
   如果要写得更细，写成一条新的、更具体的补充。已有目标里没写可观察行为的，
   正是值得补一条更可验证版本的地方。
3. **每条只讲一件事**：一条目标塞进三个能力，承接它的目就不知道要教什么。
4. **具体到可判定**：不要写「具备良好的安全意识」这种无法验收的目标；换成
   「能在拿到题目后 10 分钟内判断题型并选择入口工具」。
5. **中文作答**，术语用行业内通行写法（SQL 注入、ROP、XSS），不要中英混排成
   「SQL 的注入」。

## 输出契约

只输出一个 JSON 对象，不要 markdown 围栏，不要解释：

```json
{
  "objectives": [
    {
      "title": "能解释常见 Web 漏洞的成因",
      "type": "knowledge",
      "expectedBehavior": "能用自己的话说出 SQL 注入、文件包含、SSRF 各自的触发条件，并指出它们之间的区别",
      "minCriteria": ["三类漏洞的成因与触发条件全部说对", "能举出至少一个真实场景的例子"],
      "evidence": "理论题：漏洞成因辨析 5 题，至少答对 4 题"
    }
  ]
}
```

`objectives` 是一个数组，按 `knowledge → skill → competency → task` 排列。
`type` 只能取 `knowledge` / `skill` / `competency` / `task` 四个值之一。
